Cross-cutting invariants

Research evidence read from source on 2026-10-12; each record states what it checked. Revalidate before relying on it as live behavior.

prerequisite observed

Check: Entry 0 BOTH project halves precedes every other entry, including D baseline and frozen prototypes; ordinary dependency edges encode it.

upkeep observed

Check: Workers inspect affected topics at planning AND finish; steering receives itemless guidance. Shared access/instruction delivery must be verified; failed update records exact pending change, not false completion.

approval-is-not-current observed

Check: Record current evidence, candidate changes, approved intent and unapproved ideas separately. JOURNEYS is desired direction with execution deferred; research retention is not approval.

tree-coverage observed

Check: Every topic/command has a home or explicit gap and metadata: audience/scope, moment, teaching/recipe, deeper pointer, owner, proof. Parent coverage never implies child coverage.

required-teaching observed

Check: Shortest complete action includes needed prerequisites/results before action. Pointers supplement necessary instruction; optional suggestions use judgment.

single-authority observed

Check: One rule/recipe/definition source; preserve live facts and project policy owners. Reuse public release-matched views; never export private topology/state/secrets.

hard-versus-advisory observed

Check: 350 hard lines per teaching file/displayed response, display counted at 80-column wrapping. 20k file chars; root 40/2400, category 80/4800, command 120/7200, reply 40/2400 are advisory, not failure gates. Preserve structured/essential content.

combined-delivery observed

Check: Existing stricter byte ceilings govern complete context including messages/recovery. Optional text yields first. Native installed files and registration alone do not prove model receipt; observed QA stays separate from manifest support.

narration observed

Check: One/two sentences applies to user narration; necessary recipes retain complete teaching. Explain names/IDs and ask one recommended decision at a time.

project-bound-execution observed

Check: Global coordination may remain global; item work uses project-started session. Never switch session project or auto-launch interactive sessions. Only yoke-global is user-level; agent owns project addition.

first-item-done observed

Check: Activation extends through meaningful strategy/initiative docs, steering-created work and actual DONE. Merge is enough only under the selected completion obligations; preserve approvals/checks/project rules.

optional-setup observed

Check: Environments/previews/QA machines/plans/governance/test registration/Doctor/architecture are not universal startup gates. Unexamined remains unknown; selected work and existing rules create requirements.

delivery-obligations observed

Check: Before affected work establish landing, approval, done and QA target; configure/read back required flow. Merge-only does not remove review/QA or create post-deploy proof; preserve no-default/deferred choices and external automation.

scoped-facts observed

Check: Project/universe choices survive new machines; local prerequisites are rechecked. Do not reuse another project latest run. Settings remain authoritative; checklist/profile are views.

github-optional observed

Check: No compulsory GitHub or remote. TUI sync silently off; agent offer only relevant; later setting and deliberate permissioned opt-in. Skipped checks N/A, not fail.

permission-refusals observed

Check: Missing selection alone is project_required. Preserve permission/ambiguity/gate/capability causes, required facts and supported recovery; never reveal inaccessible projects.

installed-context observed

Check: External/global users need release-matched accessible instructions without Yoke source checkout; preserve Markdown fragments/relative links/old URLs and actual recipient context.

no-new-systems observed

Check: No artifact records/revisions, upkeep enforcement system, parallel capability registry, context subsystem, suggestion engine or imposed external doc reorganization.

filing-boundaries observed

Check: Per-project linked items, governed permanent migrations/rehearsal, prescribed workflows, frozen operator launches, investigate-only/no-code and live-code naming rules still apply.
